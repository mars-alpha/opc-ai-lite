# MVP-002 — PostgreSQL + ORM + Migration 基线

## Goal

在现有 Next.js MVP 工程中建立可追踪、类型安全、标准 PostgreSQL 可移植的第一版正式数据基线。

## ORM decision

选择 **Drizzle ORM + Drizzle Kit + postgres.js**。

原因：

- 与现有 TypeScript / Next.js 工程直接集成；
- Schema 与类型关系清晰；
- Migration 输出真实 SQL，便于审计和迁移；
- 不引入独立生成客户端运行时；
- 保持标准 PostgreSQL 可移植；
- 满足当前 MVP，不引入 Repository / Service 空架构。

## Product boundaries represented in schema

### CourseEnrollment

表达用户“加入学习”。

```text
user_id + stage_id
status
enrolled_at
completed_at
```

用户侧规则：

```text
未加入 → 加入学习（注册）
已加入 → 继续学习
```

### LessonProgress

只表达学习状态，不承担订阅或权限：

```text
NOT_STARTED
IN_PROGRESS
COMPLETED
```

唯一键：

```text
user_id + lesson_id
```

### Entitlement

独立表达访问权限。

已预留最小类型：

```text
COURSE_ACCESS
CHAPTER_ACCESS
LESSON_ACCESS
MEMBERSHIP
```

来源支持：

```text
REGISTRATION
OFFICIAL_ACCOUNT_FOLLOW
MEMBERSHIP
PROMOTION
ADMIN
```

因此“关注公众号解锁章节”不会污染 CourseEnrollment / LessonProgress。

### LessonResource

支持真实相关知识跳转：

```text
INTERNAL
OFFICIAL
FEISHU
```

当前没有为了演示写入假链接；后续只有存在真实 URL 时才创建资源记录。

## Course seed

`lib/server/db/seed.ts` 将当前静态课程映射为：

```text
Course UI 概念 → Stage
CourseModule    → Module
Lesson          → Lesson
```

当前前三 Stage / 6 个 Module / 12 个 Lesson 使用稳定文本 ID。

Seed 使用 upsert，可重复执行且不会因为 title / content / order 变化改变主键。

Lesson 当前丰富教学结构保存在 `lessons.content JSONB`，包括：

```text
plainExplanation
whyItMatters
points
content
example
guides
practice
mistakes
related
```

Practice 正式独立实体仍留到对应 Domain Task；当前 JSONB 只是 Lesson Read Model 的迁移载体。
