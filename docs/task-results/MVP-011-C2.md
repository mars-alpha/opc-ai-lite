# MVP-011-C2 — Multi-source Course Update Candidate

Status: COMPLETE_WITH_REMOTE_MIGRATION_PENDING

## Goal

把 `course_update_candidates` 从仅支持 Learning Insight 的单来源对象升级为统一多来源人工审核对象，同时保留旧 Learning Insight 链路兼容。

正式支持：

```text
LEARNING_INSIGHT → Course Update Candidate
KNOWLEDGE        → Course Update Candidate
```

两种来源统一进入 `/admin/learning`，但不共享错误的生命周期副作用。

## C2-A — Candidate Source Schema Migration

`course_update_candidates` 当前模型升级为：

```text
lessonId                 NOT NULL
sourceType               NOT NULL DEFAULT LEARNING_INSIGHT
insightId                NULLABLE
sourceKnowledgeId        NULLABLE
disposition              NOT NULL
proposal                 NOT NULL
status                   NOT NULL
reviewedBy
reviewedAt
```

旧数据自动兼容：新增 `source_type` 默认 `LEARNING_INSIGHT`，旧 `insight_id` 保持原值。

新增唯一索引：

```text
UNIQUE(insight_id)
UNIQUE(source_knowledge_id, lesson_id)
```

因此同一 Insight 不会重复产生 Candidate，同一 Knowledge 对同一 Lesson 也不会重复产生 Candidate。

Migration：

```text
drizzle/0006_square_sharon_carter.sql
```

当前项目 `DATABASE_URL` 指向 REMOTE，因此本任务没有自动执行 `npm run db:migrate`，避免擅自修改远程数据库。Migration 文件与 Drizzle snapshot 已生成并纳入 Git；部署/远程验证前必须先执行该 migration。

## C2-B — Knowledge → Candidate Admin Routing

新增：

```text
GET  /api/admin/knowledge/items/:itemId/course-candidate
POST /api/admin/knowledge/items/:itemId/course-candidate
```

在 `/admin/content` 的 Knowledge Routing 区域中新增独立：

```text
Knowledge → Course Update Candidate
```

管理员人工确认：

```text
target Lesson ID
disposition
proposedChange
rationale
affectedArea
```

生成条件：

```text
Knowledge.status = PUBLISHED
Knowledge.validity != OUTDATED / DEPRECATED
target Lesson exists
```

目标 Lesson 优先使用 Knowledge.lessonId 预填；缺失时由管理员显式输入。Candidate 的目标 Lesson 不会偷偷反向修改 Knowledge。

Knowledge Candidate proposal 结构：

```text
source = KNOWLEDGE
knowledgeTitle
knowledgeSummary
proposedChange
rationale
affectedArea
requiresHumanReview = true
```

不伪造 AI diagnosis，也不伪造 Course Insight。

## C2-C — Unified Review Service

`reviewCourseUpdateCandidate()` 已按来源分支：

```text
sourceType = LEARNING_INSIGHT
→ 更新 Candidate
→ 同步 course_insights.status

sourceType = KNOWLEDGE
→ 只更新 Candidate
→ 不修改 Knowledge.status
→ 不修改 Knowledge.validity
```

`APPROVED` 仍然只代表“批准为课程更新任务”，不会自动修改或发布 Lesson。

旧 AI 分析创建 Candidate 时现在显式写：

```text
sourceType = LEARNING_INSIGHT
insightId = current insight
sourceKnowledgeId = null
```

## C2-D — Admin Learning Workbench Source Awareness

`/admin/learning` 的 Candidate Reader 现在返回：

```text
sourceType
insightId
sourceKnowledgeId
lessonId
proposal
```

UI 会明确显示来源：

```text
LEARNING_INSIGHT
或
KNOWLEDGE
```

Learning Insight 来源继续显示 AI diagnosis / recommendation。

Knowledge 来源显示：

```text
Knowledge title
Knowledge summary
affectedArea
rationale
proposedChange
```

`NEEDS_REVISION` 在 Knowledge 来源显示为“需要修改”，不再使用“需要重新分析”的错误语义。
