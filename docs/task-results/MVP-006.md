# MVP-006 — Admin Course 最小维护与发布

## Goal

让课程内容从纯静态代码开始进入正式 PostgreSQL 后台维护流程，并建立最小 Draft / Review / Published 发布边界。

## Admin Identity

当前 MVP 不新增 Role / RBAC 数据模型。

管理员通过服务端 allowlist：

```text
OPC_ADMIN_EMAILS
```

配置。

例：

```text
OPC_ADMIN_EMAILS=admin@example.com,editor@example.com
```

后台必须先有真实 OPC Session，再根据 Session User email 做 allowlist 判断。

未登录：

```text
401
```

已登录但非管理员：

```text
403
```

## Admin UI

新增：

```text
/admin/courses
```

包含：

- Stage / Module / Lesson 课程树；
- Lesson 状态；
- Lesson version；
- title；
- summary；
- duration；
- status；
- Lesson Read Model JSON；
- 保存操作。

当前编辑器故意保持简单，没有引入富文本 CMS。

## Admin API

新增：

```text
GET /api/admin/courses
GET /api/admin/lessons/:lessonId
PUT /api/admin/lessons/:lessonId
```

PUT 只接受当前 Lesson MVP 边界：

```text
title
summary
durationMinutes
status
content
```

允许状态：

```text
DRAFT
REVIEW
PUBLISHED
ARCHIVED
```

输入会验证：

- title；
- summary；
- duration；
- status；
- Lesson Read Model 基础结构。

每次保存 version + 1。

## Frontend Published Reader

新增：

```text
lib/server/courses/reader.ts
```

Lesson 页面读取顺序：

```text
PostgreSQL PUBLISHED Lesson
↓
成功且 Payload 有效
→ 使用数据库内容

没有 PUBLISHED / DB 不可用 / Payload 无效
→ 使用 lib/courses.ts fallback
```

因此：

- DRAFT 不进入前台；
- REVIEW 不进入前台；
- ARCHIVED 不进入前台；
- PUBLISHED 才可以覆盖静态基线。

## Migration Strategy

本阶段仍处于从静态课程向数据库课程迁移的中间阶段。

`lib/courses.ts` 暂时保留，职责变为：

```text
静态结构基线
generateStaticParams
数据库异常 fallback
尚未迁移内容 fallback
```

PostgreSQL Published Lesson 已经成为正式前台优先数据源。

## Known MVP Limitation

当前 lessons 表只有一个 content/status/version 当前记录，没有 Published Snapshot 历史表。

因此：

```text
PUBLISHED → 改为 DRAFT / REVIEW
```

时，前台会回退到 `lib/courses.ts` 静态基线，而不是上一版数据库 Published Snapshot。

这在 MVP-006 接受，历史发布版本进入 Backlog，不在本任务提前扩展。
