# MVP-010-B2 — Submission Schema Validator Dispatch

Status: COMPLETE

## Goal

把 `practices.submission_schema` 从“只存字段”升级为真正参与 Runtime 的 validator dispatch，同时保持现有 `TASK_BRIEF_V1` 行为完全兼容。

## New canonical schema validator

新增：

```text
lib/server/practices/submission-schema.ts
```

提供：

```text
parsePracticeSubmissionSchema(schema)
validatePracticeSubmission(schema, content)
```

当前正式支持：

```text
TASK_BRIEF_V1
```

对应字段：

```text
Goal
Context
Input
Constraint
Output
```

每个字段：

```text
string
trim 后不能为空
最大 3000 字符
```

## Dispatch behavior

Runtime 现在先解析 Practice 自身的 `submission_schema`，再选择对应 validator。

```text
Practice.submission_schema
↓
parse schema
↓
validator dispatch
↓
normalized content
↓
Submission
↓
Evaluation
```

不再由 `interactive/service.ts` 无条件假设所有 Practice 都是 TASK_BRIEF_V1。

## Explicit failure modes

正式区分：

```text
INVALID_PRACTICE_CONTENT
INVALID_SUBMISSION_SCHEMA
UNSUPPORTED_SUBMISSION_SCHEMA
```

Submission API 映射：

```text
INVALID_PRACTICE_CONTENT     → 400
INVALID_SUBMISSION_SCHEMA    → 409
UNSUPPORTED_SUBMISSION_SCHEMA→ 409
```

Schema 是服务端 Practice 配置，不属于用户表单错误，因此 malformed / unsupported schema 不伪装成 400 用户输入错误。

## Submission flow integration

`submitPractice()` 现在顺序为：

```text
getPracticeForSubmission()
→ 获取正式 submissionSchema
→ validatePracticeSubmission()
→ 写入 practice_submissions
→ evaluatePracticeSubmission()
```

这保证 unsupported schema 在写 Submission 之前失败，不产生脏 Submission。

`evaluatePracticeSubmission()` 重新读取 Practice 的 `submissionSchema` 并再次按 schema 验证 persisted content，再交给当前 evaluator。

因此直接调用 Evaluation 也不会绕过 schema dispatch。

## Runtime validation

Validator dispatch：

```text
TASK_BRIEF_V1 + 合法五字段      → normalized content PASS
TASK_BRIEF_V1 + 缺字段           → INVALID_PRACTICE_CONTENT
UNKNOWN_V1                      → UNSUPPORTED_SUBMISSION_SCHEMA
null schema                     → INVALID_SUBMISSION_SCHEMA
```

Integration Runtime：

```text
LATEST_PRACTICE + TASK_BRIEF_V1
→ submitPractice
→ PASSED

同一 Practice 改为 UNKNOWN_V1
→ submitPractice
→ UNSUPPORTED_SUBMISSION_SCHEMA
→ 不创建第二条 Submission
```

验证后的临时用户 / Practice / Submission / Evaluation / Event 已清理。

## Architecture preserved

仍然没有引入通用表单 Builder、动态任意 JSON Schema 或第二套 Submission 系统。

当前设计是最小 registry：

```text
submission kind
→ known validator
```

以后新增 schema 时，只需要显式增加：

```text
新 kind
+ validator
+ 对应 evaluator compatibility
```

而不是修改所有 API。

## Current evaluator boundary

当前 RULE evaluator 仍只接受 `PracticeContent` / TASK_BRIEF_V1。

因此 B2 的正式事实是：

- schema dispatch 已成立；
- 只有 TASK_BRIEF_V1 注册；
- unknown schema 会明确拒绝；
- 尚未增加第二种正式 Submission Schema / Evaluator。

这避免“字段已经支持多 schema”却在 evaluator 层偷偷继续按 task-brief 处理。
