# MVP-003 — Progress / Enrollment API 与服务端学习状态闭环

## Goal

把“加入学习 / 继续学习 / Lesson 完成”从只存在于前端 localStorage 的原型状态，推进到正式 API + PostgreSQL 边界，同时在真实数据库尚未配置时保持当前原型可用。

## Result

### 1. Learning API

新增三个最小接口：

```text
GET  /api/learning/state
POST /api/learning/enroll
PUT  /api/learning/progress
```

职责：

- state：读取 CourseEnrollment + 已完成 LessonProgress；
- enroll：加入课程；
- progress：写入或撤销 Lesson 完成状态。

当 `DATABASE_URL` 未配置时，API 明确返回 `503 DATABASE_NOT_CONFIGURED`，不伪造服务端成功。

### 2. Server learning service

新增：

```text
lib/server/learning/service.ts
lib/server/learning/demo-user.ts
```

服务端通过 Drizzle 操作：

```text
users
stages
modules
lessons
course_enrollments
lesson_progress
```

当前 Auth 尚未进入 MVP，因此使用集中式 Demo User boundary。它只负责临时提供 `userId`，没有把 Demo User 写死到页面业务逻辑中。

生产模式下若仍未接 Auth，则必须显式配置 `OPC_DEMO_USER_ID`；后续 MVP-004 由真实用户身份替换。

### 3. Progress Adapter

ProgressAdapter 从原来的 load/save snapshot 调整为业务动作：

```text
load()
enroll(courseSlug)
setLessonCompleted(courseSlug, lessonSlug, completed)
```

默认使用 Hybrid Adapter：

```text
Learning API 可用 → API / PostgreSQL
Learning API 不可用 → localStorage fallback
```

Fallback 不是静默的：

- 浏览器 Console 会明确记录 API 不可用；
- 首页 Continue Learning 会显示“本机体验模式”提示；
- 本地进度仍保持可操作。

### 4. 用户侧状态

正式收敛为：

```text
未加入课程 → 加入学习
已加入课程 → 继续学习
```

Header、首页 Continue Learning、Learning Path Stage Progress 已使用 Enrollment 状态。

Lesson 完成时如果用户尚未加入该课程，会先建立 Enrollment，再记录 Progress。

### 5. 数据兼容

旧原型用户如果 localStorage 已存在 Lesson 完成记录，但没有 Enrollment 记录，Local Adapter 会将有学习进度的课程自动视为已加入，避免已有体验丢失。
