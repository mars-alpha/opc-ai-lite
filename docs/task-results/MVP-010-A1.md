# MVP-010-A1 — Practice Schema normalization

Status: COMPLETE

## Goal

在不重建 Practice 系统、不新增平行 Submission / Evaluation 表的前提下，把现有 `practices` 从“只能属于 Lesson”扩展成可以承接：

```text
LESSON_PRACTICE
STAGE_PROJECT
LATEST_PRACTICE
```

并为下一步统一 Practice Access Resolver 预留正式 ownership / access metadata。

## Schema changes

新增 enum：

```text
practice_type
- LESSON_PRACTICE
- STAGE_PROJECT
- LATEST_PRACTICE

practice_access_tier
- INHERIT
- FREE
- MEMBER
```

`practices` 新增 / 调整：

```text
type                NOT NULL DEFAULT LESSON_PRACTICE
access_tier         NOT NULL DEFAULT INHERIT
lesson_id           nullable
stage_id            nullable
source_content_id   nullable
source_knowledge_id nullable
submission_schema   JSONB NOT NULL DEFAULT { kind: TASK_BRIEF_V1 }
```

原有字段继续保留：

```text
title
goal
instructions
hints
rubric
pass_score
required
status
```

`practice_submissions` 与 `practice_evaluations` 没有新建替代模型，继续作为三类 Practice 的唯一 Submission / Evaluation 核心。

## Existing MVP-008 compatibility

现有试点：

```text
practice_task_brief_structured
```

正式状态验证为：

```text
type              = LESSON_PRACTICE
accessTier        = INHERIT
lessonId          = lesson_chatgpt_worker_task_brief
stageId           = null
sourceContentId   = null
sourceKnowledgeId = null
submissionSchema  = { kind: TASK_BRIEF_V1 }
```

Seed 已继续使用同一个 Practice，不复制数据模型。

`getPracticeForUser()` 当前阶段明确只读取 `LESSON_PRACTICE`，因此 MVP-008 旧 Submission API 不会误把尚未接入 access resolver 的 Stage Project / Latest Practice 当成 Lesson Practice。

Evaluation / Event 对 nullable `lesson_id` 已做好兼容：只有存在 Lesson ownership 时才刷新 Lesson behavior signal。

## Access metadata direction

`access_tier` 只建立 schema 事实，本阶段没有自行扩展完整权限逻辑。

下一步 A2 必须实现统一：

```text
resolvePracticeAccess(userId, practice)
```

并复用 `BIZ-FOUNDATION-001` 的 Membership Policy：

```text
INHERIT
→ 跟随所属 Lesson / Stage / Source 的正式访问规则

FREE
→ 满足身份 / 业务前置条件后免费访问

MEMBER
→ active OPC Membership
```

不允许在 Page / API 内另写第二套 `isMember` 判断。

## Ownership validation direction

正式目标约束：

```text
LESSON_PRACTICE → lesson_id required
STAGE_PROJECT   → stage_id required
LATEST_PRACTICE→ source_content_id OR source_knowledge_id required
```

A1 先完成 schema normalization；组合 ownership 校验在 A2 service resolver 中集中实现，不在数据库塞入复杂交叉 CHECK。
