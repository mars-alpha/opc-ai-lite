# MVP-005 — Entitlement + 公众号关注第一章节解锁

## Goal

在真实 User / Session / Enrollment 基础上，建立“公众号关注解锁第一章节”的最小访问控制闭环，同时不伪造真实微信公众号接入。

## Product Rule

四个状态继续独立：

```text
User / Session
CourseEnrollment
LessonProgress
Entitlement
```

公众号关注只产生 Entitlement，不改变 Enrollment 或 Progress。

## First Chapter Definition

当前第一章节固定为：

```text
Course: ai-literacy
Module: foundation
Stable Resource ID: module_ai_literacy_foundation
```

访问规则：

```text
what-is-genai → PUBLIC / 免费体验
context-token → CHAPTER_ACCESS required
```

当前 Module 只有这两课，因此受保护课时为 context-token。

## Entitlement

复用现有 `entitlements` 表，没有新增通用权限引擎。

权限记录：

```text
type         = CHAPTER_ACCESS
resourceType = MODULE
resourceId   = module_ai_literacy_foundation
source       = OFFICIAL_ACCOUNT_FOLLOW
```

有效条件：

- 未 revoked；
- expiresAt 为空或仍未过期。

## Server Enforcement

新增：

```text
lib/server/entitlements/service.ts
GET /api/learning/access
```

Lesson Access 由服务端统一判断。

`PUT /api/learning/progress` 也调用相同规则；未授权用户即使绕开 UI 直接写 Progress，也返回：

```text
403 OFFICIAL_ACCOUNT_FOLLOW_REQUIRED
```

因此锁定不是纯前端视觉效果。

## UI

Lesson 目录：

- 受限课时显示锁定图标；
- 仍可点击进入解释页面；
- 不显示课程正文。

直接访问受限 Lesson：

- 展示“关注公众号，解锁第一章节”；
- 解释关注权益规则；
- 未登录用户可先登录查看权益；
- 已登录但无权益时不提供假的“我已关注”按钮。

## WeChat Boundary

真实微信公众号尚未接入。

已提供未来服务边界：

```text
grantOfficialAccountFollowByOpenId(openId)
```

正式流程应为：

```text
微信 follow event
→ 验签
→ 幂等处理
→ OpenID
→ UserIdentity(provider=WECHAT_OFFICIAL_ACCOUNT)
→ grantOfficialAccountFollowByOpenId
→ Entitlement
```

Course / Lesson 不直接调用微信接口。

## Development Verification API

仅非 production：

```text
POST   /api/dev/entitlements/official-follow
DELETE /api/dev/entitlements/official-follow
```

必须有真实 Session。

Production 环境固定返回 404，因此不能作为线上手工解锁入口。
