# Event Momentum 目标核验：外部机制参考

日期：2026-10-17。范围：只核验时间衰减、去重与可检查报告的原始资料；这是设计研究，不是运行事实、已批准算法或质量验收结果。未修改业务代码，未执行模型或发布。

## 1. 可采用的成熟机制

| 原始资料 | 已核验事实 | 本项目适用边界 / 建议（推论） |
| --- | --- | --- |
| [Hacker News 官方 FAQ](https://news.ycombinator.com/newsfaq.html) | 基础排序随提交时间衰减；另有反滥用、过热讨论降权、站点及人工因素。不能仅凭票数和时间还原排名。 | 借鉴“时间衰减 + 独立资格/反滥用”，不能把 HN 单帖票数公式当多来源事件的成熟通用权重。 |
| [Anarki 社区维护 news.arc 排序代码](https://github.com/arclanguage/anarki/blob/master/apps/news/news.arc#L388-L464) | 可检查的排序函数结合年龄、得分及修正项，并定时重排，避免无新增互动的项目停留旧排名。 | 这是社区 fork，不是当前 HN 生产源码。可借鉴定时重新计算；项目 168h 窗口、半衰期和权重必须由自身标注样本校准。 |
| [Elasticsearch 官方 function_score 文档](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-function-score-query) | 官方定义指数、线性、高斯衰减；origin、scale、decay 分别控制位置、时间尺度、尺度处衰减值。 | 可在现有代码中实现并版本化，不需要增设 Elasticsearch。七日窗口、七日半衰期、第七日归零是三种不同产品语义；先固定语义，再评估曲线。 |
| [RFC 6596 canonical link relation](https://www.rfc-editor.org/rfc/rfc6596) | canonical 用于重复内容或内容超集的首选资源；不是“有关联就等同”的关系。 | URL 归一、转载归并与事件聚类分层；同一个模型上架多平台可归为同事件证据，不应丢弃各自材料和时间。相同名称、不同版本或不同功能不得只靠 canonical/标题相似合并。 |
| [Google 官方重复 URL 处理说明](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls) | 重定向、canonical 是较强信号，站点地图较弱；其用途包含聚合重复页信号、减少重复抓取。 | 保留原始 URL、最终 URL、canonical 和内容指纹；canonical 仅为一个可验证信号，不证明最早发布或作者独立性。 |
| [GDELT DOC 2.0 官方介绍](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/) | 提供文章列表、覆盖时间线及语言/来源维度检索；部分覆盖时间线按全部监测报道量归一。 | 可借鉴覆盖量和平台基线归一，避免接入源越多热度自然越高。索引命中只能辅助发现，不证明原创、最早发布时间或实测成功。 |
| [W3C PROV Overview](https://www.w3.org/TR/prov-overview/) | 溯源区分实体、处理活动、参与者，并覆盖派生、版本与可复现。 | 报告→声明→证据段→原始文档版本应可追踪；不要求引入 RDF/大型图数据库。 |
| [W3C Web Annotation Data Model](https://www.w3.org/TR/annotation-model/#text-quote-selector) | 注释模型支持目标资源及文本片段定位。 | 引用保留原文片段及定位、文档 hash/版本；只有 URL 而没有支持某一声明的原文不能算检查完成。 |
| [ALCE 原论文](https://arxiv.org/abs/2305.14627) | 将生成内容的正确性与引用质量分开评估；生成了引用仍可能缺少充分支持。 | 报告验收区分引用存在、引用正确、声明覆盖，不把 Schema 通过或“有链接”当事实正确。 |
| [Self-RAG 原论文](https://arxiv.org/abs/2310.11511) | 研究按需检索、相关性判断与生成检查，指出无差别纳入固定检索段落的局限。 | 借鉴证据缺口驱动的定向补发现；不据此要求部署专门训练模型，也不让模型猜测补成事实。 |

## 2. 对目标的具体建议（待规格确认）

- 热度与价值分开：代码按独立原创发布者、时效、实际讨论和实操证据生成可解释热度；AI 从有证据的内容分析价值，不直接授予热度或栏目权威。
- 按真实新增信号的发生时间衰减；重复采集、同作者跨平台发布、转载和反复读取不新增独立热度。保存事件首发时间，不用最新采集时间把旧发布变成新发布。
- 同一事件七日后仍有新实质信号时，应区分“原始发布年龄”和“近期事件动量”；是否复燃、关联为后续事件，由明确合同决定，不能一边累加信号、一边仅因 firstSeenAt 超过 168h 永久失效。
- 最早发布时间只能写“已核验材料中最早”，并记录精度、时区、依据；原作者/官方原文和最早被本站发现的页面分开，禁止把最早搜索结果当互联网全局首发。
- 关联时间线保留每项证据发布时间、首次 SYSTEM 发现时间和抓取时间；历史分数存实际 asOf 快照，不能事后影子重算后标成当时排名。
- 报告分清事实、作者声称、实测结果、分析推断和学习建议。对比必须有同版本、同任务和相容测试条件；没有对照证据则明确无法得出提升幅度。
- 抓取失败时 AI 只生成作者/产品/别名/版本的查询计划；检索获得候选 URL 后仍走原 Source 身份、路由资格、抓取和证据校验。403、超时、未知路由、未登录分别处理；AI 不绕过访问资格，不从摘要编造原文，不自动执行仓库脚本或工作流。
- 没有官方原始资料可支持本项目的具体热度阈值、权重或半衰期。采用冻结正负例、独立标注、时间切分回放比较候选参数，保留版本和回滚，不凭参考系统的常数定案。

## 3. 最低验收建议（推论）

1. 无新信号时分数随时间不增加；重复/转载/同作者镜像不增加独立发布者计数。
2. 固定 asOf、输入证据版本、算法版本可复算同一分数；排名分解可解释每项纳入/排除原因。
3. 最早原文无法证明时保持未知；时间修正、拆分/合并保留审计。
4. 报告所有事实与数字必须关联可访问证据片段；没有足够实测条件不得输出确证的效果结论。
5. 补发现失败不改变资格、热度、实测状态；新候选不因 AI 推荐即成为成熟 Source。
