## T5-10 — 原型不是“小号正式系统”，只验证最关键假设
Primary Knowledge Home: **Prototype Hypothesis / Minimum Proof**
Core judgment: Prototype 只验证最关键且最不确定的假设；如果没有明确假设，做得再像正式系统也只是 Demo。
Must-retain judgments:
- 一次原型优先验证一个高风险未知；
- 最小证明可能是人工模拟、样例数据或轻量拼装；
- “功能齐全”不是原型成功标准；
- 证据必须能改变下一步决策。
Practice: 学员自己的 Prototype Hypothesis；字段包括方案、最关键未知、为什么重要、最小证明方式、观察结果、停止/通过信号、希望 AI 帮我缩小什么。

## T5-11 — Pilot 应该找谁试、试什么、什么情况下立即停
Primary Knowledge Home: **Pilot Design / Users / Scenario / Guardrails / Stop Rule**
Core judgment: Pilot 是在真实工作里受控验证，不是“找几个人随便试试”；必须先定义真实用户、场景、证据、护栏与停止条件。
Must-retain judgments:
- Pilot 用户要能代表真实使用情境；
- 场景范围要窄且可观察；
- 护栏与停止条件必须预先定义；
- Pilot 成功条件来自 T5-05，不临场改规则。
Practice: 学员自己的 Pilot Plan；字段包括谁试、在哪个真实场景、要观察什么、怎样记录、哪些动作必须人工确认、什么情况立即停、希望 AI 帮我检查什么。

## T5-12 — Pilot 出问题时，先改方案还是先改使用方式
Primary Knowledge Home: **Pilot Learning / Failure Classification / Iteration Decision**
Core judgment: Pilot 出问题时要先分辨是方案、数据、流程、使用方式还是环境造成，再决定修改什么；不能把所有失败都归因于“AI 不够好”。
Must-retain judgments:
- 分类问题先于修改方案；
- 单次异常不自动代表系统性失败；
- 使用摩擦可在 Pilot 阶段记录，但不提前教授 Adoption；
- 每次修改要对应一个可验证的原因假设。
Practice: 学员自己的 Pilot Learning Log；字段包括异常现象、发生场景、现有证据、可能类别、还缺什么、下一轮只改什么、希望 AI 帮我判断什么。

## Cross-lesson acceptance
Prototype = 验证关键假设；Pilot = 真实受控使用；Pilot Learning = 根据证据迭代。不得混同。
