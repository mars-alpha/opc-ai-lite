## Batch goal
把线索继续推进到可控的人际沟通与服务边界：
**先搞清客户上下文 → 有目标地跟进 → 客服先找依据 → 高风险场景知道停下**。

## T3-10 — 跟进客户前，先把背景和真实需求搞清楚
Primary Knowledge Home: 客户上下文 / 需求提取。
- 已知事实 / 客户原话 / 内部推测 / 冲突 / 待确认必须分开。
- Practice：客户资料/对话 → 客户上下文简报 → 3个关键澄清问题。
- AI 不猜预算、授权、购买意向、最终解决方案。
- Capability：跟进前说清“知道什么、还不知道什么、下一步问什么”。

## T3-11 — 客户没回复或有异议，下一步怎么跟进
Primary Knowledge Home: 销售跟进 / 异议处理。
- 跟进不是重复催促，每次只解决一个当前问题。
- Practice：未回复/异议 → 跟进目标 → 可用证据 → 消息草稿 → 下一步/暂停条件。
- 最终发送、价格、折扣、效果承诺、让步由人确认。
- Capability：知道为什么发、发什么、发完期待什么、何时停。

## T3-12 — 客服回复为什么必须先找到依据
Primary Knowledge Home: 基于可信资料的客服答复。
- 回答前先找当前有效、可追溯事实源。
- Practice：当前维护中的知识资料 → 客服答复 + 内部依据 + 缺失信息。
- AI 不把旧回复、常识或模型记忆当成当前政策，也不能自行指定哪份资料是最终事实依据。
- Capability：关键结论可追溯；证据不足会停止强答。

## T3-13 — 什么情况不能继续自动回答，必须停下来转人工
Primary Knowledge Home: 服务边界 / 转人工 / 风险判断。
- 继续答 / 先澄清 / 转人工三类业务规则。
- Practice：退款、投诉、敏感信息、账号权限、规则冲突、未知答案 → 业务边界表。
- 只定义继续回答、先澄清、转人工及交接信息，不扩展到系统实现。
- Capability：识别必须停下的风险与权限场景，并说清人工接手信息。

## Acceptance
T3-10～13 都必须使用真实业务材料；任何客户事实、规则、承诺、权限不得由 AI 补写。T3-13 必须确保课程只讲服务边界与人工接手判断，不引入后续系统架构内容。
