## 1. Purpose

Stage 1 + Stage 2 不再作为八节彼此独立的 Beginner Lesson，而是作为一条连续能力链。

固定学习体验：

```text
一个真实内容 / 业务想法
→ 先让 AI 帮上忙
→ 看见结果为什么会变化
→ 知道哪些内容不能直接相信
→ 知道什么时候该给 AI 更多资料 / 使用搜索或文件
→ 把任务说清楚
→ 把必要 Context 补齐
→ 根据第一版继续改
→ 发布 / 交付前完成最小核实
```

最终 Artifact：

**Verified Publishable Draft（经过基本核实、可以继续进入工作应用 / 内容运营的成品草稿）**

Stage 1 负责：
**第一次把事情做起来 + 建立最低必要世界观。**

Stage 2 负责：
**继续同一个 Artifact，把它从“AI 给了一个结果”做到“我能控制并交付这个结果”。**

---

## 2. Default Case Thread

默认贯穿案例：

**为 OPC / 自媒体制作一篇“最近一个值得关注的 AI 变化 / 工具 / 使用方法”的内容草稿。**

学习者不是为了学“怎么运营 OPC”才完成任务，而是借这个案例练习通用 AI 协作方法。

默认业务 Context：

- 发布主体：OPC / 个人自媒体；
- 目标受众：刚开始学 AI、希望实际使用 AI 的普通用户；
- 内容目的：把一个 AI 主题讲清楚，让用户知道它有什么用；
- 内容形式：短图文 / 公众号短文 / 社媒帖子均可；
- 质量要求：易懂、具体、不夸大、事实可核实；
- 后续用途：Track 02 可继续用于 Research / Writing / File / Data / Knowledge；Track 03 可继续用于分发、获客和业务转化。

行业替换不改变方法：

```text
OPC / 自媒体
AI 主题 → 内容草稿

房地产
楼盘 / 市场信息 → 客户内容草稿

电商
产品 / 使用场景 → 商品内容草稿

教育
课程 / 知识点 → 招生或教学内容草稿

企业服务
业务问题 / 解决方法 → 专业内容草稿
```

替换的只有主题、资料、受众和业务约束。

# 4. Stage 1 — 第一次把 AI 真正用起来

## F1-01 — beginner-ai-use-cases

Title: **AI 到底能帮我做什么**  
Type: **APPLICATION**  
Planned Gate: **CHECK + PRACTICE**  
Primary Knowledge Home: **Everyday AI use cases**

### Current Learner Job

从一个真实 OPC / 自媒体内容需求开始，判断 AI 可以在哪些部分帮忙，并让 AI 产出第一版。

### Inherited Capabilities

无。

### Inherited Artifact / Context

一个真实内容想法，例如：

> “最近看到一个 AI 工具 / 功能变化，我想做一篇内容告诉普通人它有什么用。”

### New Capability

能把真实工作拆成“AI 可以协助的部分”和“仍需要自己判断的部分”，并实际让 AI 完成第一个小任务。

### Artifact Action

选择一个真实主题，让 AI 先生成一版内容草稿。

### Artifact Output

**AI First Draft**

这份 Draft 不要求质量高，也不要求已经核实；它是后续七节课持续加工的起点。

### Next Reuse

F1-02 直接比较这份 Draft 在信息变化后为什么结果会不同。

### Do Not Re-teach

- 不提前教 Prompt 结构；
- 不教 Context 定义；
- 不教 Hallucination 定义；
- 不教模型内部机制；
- 不讲完整内容运营方法。

### Human Review Focus

学习者是否在第一节就真正“用了一次 AI”，并留下后续可以继续加工的东西，而不是只学“AI 能做哪些类别”。

## F1-02 — beginner-ai-result-quality

Title: **为什么同一个 AI，有时好用、有时不好用**  
Type: **APPLICATION**  
Planned Gate: **CHECK + PRACTICE**  
Primary Knowledge Home: **Input quality → result quality intuition**

### Current Learner Job

拿 F1-01 的 AI First Draft 做一次最小对比实验：只补一个真正重要的信息，看结果发生什么变化。

### Inherited Capabilities

- 已知道 AI 可以协助真实任务；
- 已经完成过一次真实生成。

### Inherited Artifact / Context

F1-01 的 **AI First Draft** + 原始模糊需求。

### New Capability

形成最基础的因果直觉：

**AI 的结果会受到你给它的信息影响；当结果不好时，先检查任务信息，而不是只判断“这个 AI 行不行”。**

### Artifact Action

只补一个关键变量，例如：

- 目标受众；
- 内容目的；
- 输出形式。

然后比较 Before / After。

### Artifact Output

**Selected Better Draft + Result Comparison Note**

学习者保留：
- 原始版本；
- 修改后版本；
- “哪个信息让结果变好”的一句判断。

### Next Reuse

F1-03 继续检查这个“更好的 Draft”里面，哪些内容依然不能直接相信。

### Do Not Re-teach

- 不正式定义 Prompt；
- 不给 Prompt 万能公式；
- 不正式定义 Context；
- 不教 Iteration；
- 不讲 Token / Context Window。

### Human Review Focus

这一课必须是“小实验”，而不是提前变成 F2-01 Prompt 课。

---

## F1-03 — beginner-ai-can-be-wrong

Title: **AI 为什么会说错，而且还说得很像真的**  
Type: **CONCEPT**  
Planned Gate: **CHECK**  
Primary Knowledge Home: **Hallucination / verification intuition**

### Current Learner Job

检查当前 Draft：哪些句子属于“写得顺就可以”，哪些句子如果写错会真的误导别人。

### Inherited Capabilities

- 已经有一个改进后的 Draft；
- 知道输入会影响输出质量。

### Inherited Artifact / Context

F1-02 的 **Selected Better Draft**。

### New Capability

不是学习“Hallucination”术语，而是形成使用判断：

**AI 写得自然、确定，不等于事实正确。**

### Artifact Action

在当前 Draft 中标记：

- 纯表达 / 创意；
- 事实；
- 数字 / 日期 / 最新信息；
- 自己不确定的内容。

### Artifact Output

**Draft + Verification Flags**

只标记“哪些地方需要注意”，本课不教授完整检查流程。

### Next Reuse

F1-04 决定这些 Flags 应该通过什么产品能力 / 资料方式补足。

### Do Not Re-teach

- 不讲概率生成机制；
- 不讲 Token；
- 不教正式 Verification Framework；
- 不展开“事实性 / 风险 / 可验证性”三维判断；
- 不要求本课完成全部核实。

### Human Review Focus

必须清楚区分：
F1-03 = **发现风险**；
F2-04 = **决定检查力度并完成检查动作**。

## F1-04 — beginner-ai-product-map

Title: **AI 软件里的模型、搜索、文件和记忆是什么关系**  
Type: **CONCEPT**  
Planned Gate: **CHECK**  
Primary Knowledge Home: **AI product capability map**

### Current Learner Job

面对 F1-03 标出的内容缺口，知道下一步应该：
- 继续直接和 AI 对话；
- 给它文件 / 资料；
- 使用搜索；
- 或保留必要的上下文。

### Inherited Capabilities

- 能让 AI 完成一个任务；
- 知道结果受信息影响；
- 能发现 Draft 中需要注意的事实位置。

### Inherited Artifact / Context

F1-03 的 **Draft + Verification Flags**。

### New Capability

形成一个极简产品能力地图：

**模型负责生成 / 理解；产品可以额外提供搜索、文件、记忆等能力，帮助 AI 获得当前任务需要的信息。**

重点是“选择能力”，不是理解技术架构。

### Artifact Action

针对当前 Draft 的 2–3 个信息缺口，判断最合适的下一动作：
- 直接补充说明；
- 给文件；
- 搜索最新资料；
- 保留后续需要的背景。

### Artifact Output

**Prepared Draft + Source / Capability Plan**

### Next Reuse

F2-01 不再讨论“为什么信息会影响结果”，而是直接正式学习怎样把当前任务说清楚。

### Do Not Re-teach

- 不正式讲 Model vs Product；
- 不讲 API / Tool / RAG；
- 不讲 Memory 技术机制；
- 不把 Search 课提前搬进 Foundation Stage 1；
- 不重新解释 AI 会错。

### Human Review Focus

这一课应让用户知道“下一步应该怎么给 AI 更多能力 / 信息”，而不是变成 AI 产品术语百科。

# 5. Stage 2 — 把同一个结果做到可用

Stage 2 不重新证明“信息会影响结果”、不重新证明“AI 会错”。

Stage 2 的统一入口：

> 你已经有一个 AI Draft，也知道它为什么可能不够好。现在开始真正控制这个结果。

## F2-01 — beginner-prompt

Title: **Prompt：怎样把想做的事情说清楚**  
Type: **APPLICATION**  
Planned Gate: **CHECK + PRACTICE**  
Primary Knowledge Home: **Prompt foundations**

### Current Learner Job

把此前零散的任务要求整理成一份 AI 可以直接执行、自己也可以检查的 Task Brief。

### Inherited Capabilities

- 会选择 AI 适合做的任务；
- 知道信息变化会影响结果；
- 已体验过一个内容任务。

### Inherited Artifact / Context

F1-04 的 **Prepared Draft + Source / Capability Plan**。

### New Capability

把 Prompt 正式理解为：

**当前这一次交给 AI 的清楚任务说明。**

只训练三个问题：
- 要做什么；
- 哪些必要背景已经确定；
- 希望得到什么结果。

### Artifact Action

基于已有内容主题，整理当前任务。

### Artifact Output

**Clear Task Brief + New Draft**

### Next Reuse

F2-02 将检查 Task Brief 之外，AI 还缺哪些品牌、受众、资料和当前事实。

### Do Not Re-teach

- 不再解释“说清楚为什么会让结果变好”；
- 不重新做 F1-02 Before / After 论证；
- 不教万能 Prompt 模板；
- 不教 System Prompt / Prompt Engineering；
- 不提前讲 Context Window。

### Human Review Focus

用户应该感觉“终于把前面的经验整理成一个正式方法”，而不是“前面讲过的输入清楚再讲一次”。

## F2-02 — beginner-context

Title: **Context：AI 只知道你这次给它看到的东西**  
Type: **CONCEPT**  
Planned Gate: **CHECK**  
Primary Knowledge Home: **Task Context**

### Current Learner Job

检查当前任务：除了 Task Brief 之外，AI 真正还需要哪些现成资料 / 品牌背景 / 受众信息 / 当前事实。

### Inherited Capabilities

- 已能写清 Task Brief；
- 已知道需要时可以给 AI 搜索 / 文件 / 信息。

### Inherited Artifact / Context

F2-01 的 **Clear Task Brief + New Draft**。

### New Capability

正式建立 Task Context：

**AI 当前完成任务时真正可以使用的信息集合。**

### Artifact Action

为当前 OPC / 自媒体内容补齐一个最小 Context Pack，例如：
- OPC / 账号定位；
- 目标读者；
- 当前主题资料；
- 要保留的事实 / 来源；
- 不应该自行猜测的内容。

### Artifact Output

**Context Pack + Context-enriched Draft**

### Next Reuse

F2-03 直接拿 Context-enriched Draft 继续改，而不是重新生成另一个无关案例。

### Do Not Re-teach

- 不再解释“你知道 ≠ AI 知道”作为整节主线；F1 已有直觉；
- 不重讲搜索 / 文件的产品能力；
- 不讲 Token mechanics；
- 不讲 Context Window；
- 不讲 Context Engineering。

### Human Review Focus

重点是“给当前真实任务装好正确材料”，不是 Context 定义考试。

## F2-03 — beginner-iteration

Title: **第一次结果不对，怎样继续让 AI 改好**  
Type: **APPLICATION**  
Planned Gate: **CHECK + PRACTICE**  
Primary Knowledge Home: **Iteration / clarification**

### Current Learner Job

拿 Context-enriched Draft，指出最影响发布的一到两个偏差，并推动下一轮改进。

### Inherited Capabilities

- 会写 Task Brief；
- 会补 Context；
- 已经有一个资料更完整的 Draft。

### Inherited Artifact / Context

F2-02 的 **Context-enriched Draft**。

### New Capability

把 AI 协作从“一次生成”升级为：

**保留有效部分 → 指出具体偏差 → 补信息 / 示例 → 必要时让 AI 先问清楚 → 再修改。**

### Artifact Action

对当前 Draft 做一轮明确改稿。

### Artifact Output

**Iteration Notes + Iterated Draft**

### Next Reuse

F2-04 将直接对 Iterated Draft 做发布前检查。

### Do Not Re-teach

- 不重讲 Prompt 三要素；
- 不重讲 Context 定义；
- 不重新解释“信息会影响结果”；
- 不教 Workflow Loop；
- 不教 Agent Self-correction。

### Human Review Focus

Practice 必须真的修改当前 Artifact，而不是再写一条独立客户消息。

## F2-04 — beginner-result-check

Title: **AI 的结果什么时候能直接用，什么时候一定要检查**  
Type: **APPLICATION**  
Planned Gate: **CHECK + PRACTICE**  
Primary Knowledge Home: **Basic reliability judgment**

### Current Learner Job

当前 Draft 已经准备发布 / 交付。学习者要决定哪些地方可以直接保留，哪些地方必须核实，并完成最小检查动作。

### Inherited Capabilities

- F1-03：能发现哪些内容值得警惕；
- F1-04：知道可能需要搜索 / 文件 / 原始资料；
- F2-01～03：已经形成并迭代一份真实 Draft。

### Inherited Artifact / Context

F2-03 的 **Iterated Draft + Verification Flags / Source Plan**。

### New Capability

建立最小可靠性判断：

- 这是事实还是创意 / 表达；
- 如果错了，实际代价多大；
- 有没有独立可靠来源可验证。

### Artifact Action

对当前 Draft 中至少一条事实性内容完成：
- 风险判断；
- 来源确认；
- 必要修订。

### Artifact Output

**Verification Record + Verified Publishable Draft**

### Next Reuse

Track 01 Stage 3 可用这个真实经验解释 Model / Generation / Context Window；Track 02 直接拿这份 Verified Draft 扩展 Research / Writing / Files / Data / Knowledge 工作能力。

### Do Not Re-teach

- 不再讲“AI 会错”；
- 不再用“语气很确定也可能错”作为主要新知识；
- 不教完整 Evaluation Framework；
- 不教 Test Set / Regression；
- 不要求对所有创意内容逐句核实。

### Human Review Focus

用户必须实际完成至少一个“回到可靠来源确认”的动作设计，而不只是再做一次真假判断题。

# 6. What We Keep / Move / Remove

## Keep

当前 Stage 1 / Stage 2 中以下教学资产可以继续复用思想：

- Beginner-first；
- 一节一个主问题；
- Example before definition；
- Before / After；
- Three-Question Mastery；
- Guided Practice / Hint / Reference；
- COPY_TO_AI；
- AI-tool-neutral；
- Cognitive Load Budget；
- F1-03 的“语气不是证据”直觉；
- F2-03 的“指出具体偏差再改”方法；
- F2-04 的事实性 / 风险 / 可验证性框架。

## Move / Narrow

### F1-02

保留“输入变化 → 结果变化”的体验，但只作为一个最小实验。

Prompt 正式方法全部留给 F2-01。

### F1-03

保留“AI 结果不能因语气自然就直接相信”。

完整“怎么检查、检查多少”全部留给 F2-04。

### F1-04

保留极简产品能力地图，但必须服务当前 Draft 的“下一步怎么办”。

Model vs Product 正式概念仍留 F3-01。
Memory / RAG / Search 机制仍留后续 Primary Knowledge Home。

### F2-02

正式定义 Task Context，但不再把“AI 不知道你脑里的背景”当成整节重复解释。

重点转为建立 **Context Pack**。

## Remove as Duplicate

新 Draft 生产时应删除 / 避免：

- F2-01 再次用一整节证明“输入清楚 → 结果更好”；
- F2-02 再次从零解释“你知道 ≠ AI 知道”；
- F2-04 再次从零解释“AI 会说错”；
- 每节更换为无关的客户通知 / 政策 / 活动案例；
- Capability 只写“理解了 Prompt / Context / Verification”；
- nextLessonValue 只预告下一个知识名词。

# 8. Stage 1 Lesson Separation Decision

F1-02 / F1-03 / F1-04 继续保持独立 Lesson，但必须全部围绕同一 Artifact Thread 重构。

理由：

### F1-02 必须独立

它负责建立“输入变化会影响结果”的最基础实验直觉，是 F2-01 Prompt 之前的重要体验证据。

### F1-03 必须独立

它负责建立“结果好看 ≠ 事实正确”的安全边界，是后续所有工作应用的基础。

### F1-04 必须独立

它负责建立“遇到信息缺口时，可以通过产品能力 / 资料补足”的极简地图，为 F2-02、Stage 4 Knowledge/RAG、Track 02 Research 打基础。

但三节都不得继续作为孤立理论课。
