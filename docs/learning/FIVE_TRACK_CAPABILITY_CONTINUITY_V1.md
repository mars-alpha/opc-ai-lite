# Five-Track Capability Continuity Baseline v1

Status: **APPROVED_BASELINE_V1**  
Task: **CURRICULUM-CONTINUITY-001 — Five-Track Capability Continuity Baseline**

## 1. Core principle

OPC 五大长期板块不是五套独立课程，而是一条连续能力链：

```text
01 AI 基础认知
→ 正确使用 AI，并建立基本协作能力

02 AI 工作应用
→ 用已经掌握的 AI 协作方法完成真实工作

03 AI 推广运营与业务增长
→ 把真实工作成果转成内容、流量、线索与业务机会

04 AI Workflow 与自动化
→ 把已经验证有效的方法固化为可重复、可控、可评估的流程

05 FDE / AI 解决方案落地
→ 面向完整业务问题设计、验证并推动 AI 解决方案落地
```

课程价值判断固定为：

**学完能继续做什么，比学完记住什么更重要。**

### 1.1 Five-track curriculum is capability-complete, not lesson-count-complete

五大板块都不以固定课数作为完成标准。

每个 Track 的课程数量由 **Exit Capability 是否完整形成** 决定：
- 如果现有课程足以让学习者稳定完成该 Track 的真实任务，不为“内容丰富”继续加课；
- 如果 Human Review / Practice / Project / Learner Evidence 发现关键能力断层，可以继续增加课程；
- 新课程必须说明它修复哪个能力缺口，以及后续 Track 怎样复用；
- 课程目录可以扩展，但五大板块的能力方向保持稳定。

因此 Track 01 当前 20 节是 Core Baseline，不是上限；Track 02～05 未来也采用同一规则，不预先锁死课数。


## 2. Universal method vs case layer

课程必须分为两层。

### Stable Method Layer

长期稳定、行业无关：

- 明确目标
- 提供必要信息
- 生成 / 分析 / 整理
- 迭代
- 验证
- 形成可用结果
- 复盘
- 复用
- 自动化
- 解决完整业务问题

这一层适用于自媒体、房地产、电商、教育、企业服务等行业。

### Swappable Case Layer

默认贯穿案例优先使用：

**OPC / 自媒体 / 内容运营 → 推广 → 获客 → 业务转化**

原因：
- 能覆盖 Research / Writing / Media / Distribution；
- 能自然连接推广、销售、客服、数据分析；
- 能继续升级为 Workflow / FDE；
- 用户可以直接在 OPC 或自己的自媒体中实践。

行业替换时只更换场景、资料、渠道和业务约束，不改变核心方法。

可替换行业：
- 房地产
- 电商
- 教育
- 咨询 / 企业服务
- 本地生活
- 其他内容驱动或获客型业务

## 3. Five-track continuity contract

| Track | Inherit | Add | Learner Output | Exit Capability | Next Track Reuses |
| --- | --- | --- | --- | --- | --- |
| 01 AI 基础认知 | 零基础 | 正确使用、协作、判断 AI | 一个经过 Prompt/Context/Iteration/Check 打磨的真实内容/工作产物 | 能正确和 AI 协作完成一个任务 | Track 02 直接复用协作方法和已有产物 |
| 02 AI 工作应用 | Track 01 协作方法 | Research/Writing/File/Data/Knowledge 等工作能力 | 一组真实工作产物 | 能用 AI 完成常见工作 | Track 03 复用研究、内容、数据和资料 |
| 03 推广运营与业务增长 | Track 02 工作产物 | 内容运营、分发、获客、销售、客服、运营分析 | 内容资产、渠道素材、Lead、跟进/客服方案、运营复盘 | 能把 AI 工作结果转成业务机会 | Track 04 选择已验证的重复业务链路 |
| 04 Workflow 与自动化 | Track 03 已验证流程 | Task Decomposition、Context Engineering、Code/Skill/Tool、Automation、HITL、Evaluation | 可执行 Workflow 方案 / Prototype | 能把有效方法变成稳定流程 | Track 05 将 Workflow 放入完整业务问题 |
| 05 FDE | Track 04 Workflow 能力 | Problem Discovery、Value、Solution Design、Pilot、Evaluation、Adoption | 完整 AI Solution Package | 能发现并推动真实 AI 解决方案 | 形成真实项目 / 企业落地能力 |

### 3.1 Five-track integration model

五大板块不是“基础课 → 五套新内容”，而是同一对象持续升级：

| Transition | 前一板块保留下来的东西 | 下一板块新增什么 | 结合方式 |
| --- | --- | --- | --- |
| Track 01 → 02 | Task Brief、Context、Iteration、Verification 方法 + 一个真实任务产物 | Research / Writing / Files / Data / Knowledge 工作技能 | 不重教 Prompt；直接拿已有方法去做更多工作 |
| Track 02 → 03 | 研究结果、内容、文件、数据、知识资产 | 内容运营、推广、获客、销售、客服、运营分析 | 把“工作产物”变成“业务动作与业务结果” |
| Track 03 → 04 | 已经人工跑通且证明有效的业务链路 | Workflow、Automation、Skill / Tool / Code、HITL、Evaluation | 只自动化已经理解和验证的流程 |
| Track 04 → 05 | 可执行 Workflow、指标、异常、权限、人工确认点 | Problem Discovery、Value、Solution Design、Pilot、Adoption | 不从零做 Demo，而是把已有流程放进完整业务问题 |
| Track 05 → Real Project | Solution Package、Pilot Evidence、Adoption Plan | 企业 / 项目真实实施 | 形成可交付的 FDE / AI 解决方案能力 |

统一纵向主线：

```text
一个真实任务
→ 做出可靠工作产物
→ 让产物产生业务价值
→ 把有效业务流程系统化
→ 把系统化能力组合成完整 AI 解决方案
```

任何新增课程都必须能标注自己位于这条链的哪一段，以及它的输出由哪个后续模块继续使用。


## 4. Lesson continuity rules

每节正式课程在 Brief 阶段必须回答：

```text
Inherited Capability
Inherited Artifact / Context
Current Learner Job
New Capability
Artifact Action
Artifact Output
Next Reuse
Anti-repeat Boundary
```

固定规则：

1. 不重复教授已完成的 Primary Knowledge Home。
2. 后续课默认“调用已学能力”，而不是重新解释。
3. 能复用上一课产物时，优先继续同一产物。
4. APPLICATION / PRACTICE / PROJECT 原则上必须产生或改善一个可用产物。
5. CONCEPT 可以没有正式 Deliverable Gate，但必须解释该概念会改变学习者哪一个真实动作/判断。
6. 同一个 Production Batch 优先使用贯穿案例，而不是每节重新开无关场景。
7. 下一节必须能明确说出会继续使用上一节的什么。
8. “下一课价值”不能只是预告知识点，应说明下一步会拿当前能力/产物做什么。
## 4.1 Six-step continuity applies across all five tracks

五大板块的每一个新 Primary Knowledge Point 都必须用统一六步检验，并同时遵守 Continuity Contract。

因此后续课程设计同时满足两条轴：

- 横向：单个知识点内部必须通过 EXPLAIN → EXAMPLE → CHECK → PRACTICE → REVIEW → CAPABILITY；
- 纵向：当前 Lesson 的 Inherited Capability / Artifact 必须承接前课，Capability / Artifact Output 必须能继续被后课复用。

六步解决“这一课有没有真正教会”，Continuity 解决“这一课是不是接在正确的位置”。两者缺一不可。

课程目录设计还必须先经过 Capability-first Audit：先定义五大板块最终能力，再确定支撑能力的 Knowledge，最后使用 Six-step 判断哪些知识值得独立成课。固定顺序为：Capability Map → Knowledge Map → Six-step Audit → Course Directory。不能因为存在 Token / RAG / API / MCP / Agent 等专业名词，就默认一词一课。

## 5. Longitudinal artifact model

课程不要求所有课共享一个永久文件，但必须有连续的 Artifact Thread。

默认 OPC / 自媒体主线可使用：

```text
一个内容/业务想法
→ 清楚任务 Brief
→ 补齐资料与品牌 Context
→ AI 初稿
→ Iterated Draft
→ Verified Draft
→ Research / Content Assets
→ Multi-channel Content Package
→ Distribution / Lead Capture
→ Sales / Customer Service Follow-up
→ Operations Review
→ Repeatable Workflow
→ Business AI Solution
```

用户应持续感觉“我在把同一件事做得更完整”，而不是每节课重新开始。

## 6. Track 01 reframe

Track 01 不再以“先解释知识”为主线，而是：

**第一次把一个真实 AI 任务做完整，同时逐步建立必要世界观。**

Stage 1：
- 选一个和自己业务/内容相关的真实任务；
- 看见 AI 能做什么与不能做什么；
- 产生第一版结果；
- 建立“结果会变、AI 会错、产品能力不同”的基础判断。

Stage 2：
- 继续 Stage 1 同一个任务；
- Prompt：把需求说清楚；
- Context：补 OPC / 品牌 / 受众 / 资料；
- Iteration：把初稿改到可用；
- Result Check：发布/交付前核实关键事实。

Stage 3+：
在用户已经有真实使用体验后，再解释 Model / Training / Token / Context Window 等机制，并要求每个机制概念回扣此前真实体验。

## 7. Track 02 continuity

Track 02 是五轨中的“使用能力转换层”：Track 01 已经解决“AI 是什么、怎样正确协作”，Track 02 负责把这些能力转成稳定日常工作能力。

统一入口：

> 你已经知道怎么和 AI 协作；现在要做到工作遇到问题时，知道怎么问、怎么做、怎么检查、怎么继续。

当前唯一 Track 02 Context Owner：`docs/learning/TRACK02_CATALOG_CONTEXT_V1.md`。

内部能力域依次扩展为 Research / Evidence、Writing / Communication、Document / File Work、Data / Spreadsheet Work、Knowledge Work、Reusable Work Method；对学习者则统一使用 Track 02 owner 中的结果型 Phase 表达。

当前结果型能力结构固定为：

```text
会找答案 → 会做成品 → 会处理复杂资料 → 会看数据 → 会积累知识 → 会复用方法
```

Track 01 的 Prompt / Context / Reliability / Search / RAG / Structured Output / Multimodal / Skill / Workflow / Agent / HITL 在 Track 02 只被调用，不重新从定义教学。Track 02 产生的 Research、Deliverable、Document Findings、Action、Data Insight、Knowledge Pack、Reusable Method 由 Track 03 转成业务结果；Workflow Design / Automation / Reliability / HITL / Evaluation 留给 Track 04；完整 Problem → Solution → Pilot → Adoption 留给 Track 05。

## 8. Track 03 continuity

统一入口：

> 你已经能完成工作，现在让这些工作产生曝光、线索与业务价值。

当前唯一 Track 03 Context Owner：`docs/learning/TRACK03_CATALOG_CONTEXT_V1.md`。

当前结果型能力链：

**找对业务对象 → 做成内容资产 → 发布并承接线索 → 推进销售 → 做好客服 → 用数据复盘增长**

默认 OPC / 自媒体 Artifact Thread 从 Track 02 Research / Content / Data / Knowledge Assets 开始，依次形成 Audience & Use-case Card、Message Hierarchy、Topic/Series、Multimodal Asset Pack、Channel Distribution、Conversion Path、Lead、Sales Follow-up、Service Response、Operations Review 与 Growth Review。方法必须可替换到房地产、电商、教育、企业服务。

Track 03 的终点不是 Automation，而是“已经人工跑通、能衡量、值得重复”的业务链路；Track 04 才负责系统化。

## 9. Track 04 continuity

统一入口：

> 前面的流程已经人工跑通，现在把重复、稳定、值得复用的部分系统化。

只自动化已经理解/验证的流程。

禁止为了教 Workflow 而凭空创造与前面业务无关的新流程。

## 10. Track 05 continuity

统一入口：

> 现在不再只优化一个任务，而是解决一个完整业务问题。

FDE Capstone 必须尽量复用前面已经形成的：
- Business Context
- Content / Research Assets
- Workflow
- Evaluation evidence
- Human Review points

## 11. Course Builder boundary

Course Builder 不拥有课程顺序，也不决定跨课程 Workflow。

Curriculum / Formal Brief 负责：
- 顺序
- prerequisite
- inherited capability
- longitudinal artifact
- next reuse

Course Builder 负责：
- 消费这些 continuity context；
- 生成不重复、能承上启下的单节 Lesson Draft；
- 在当前课中正确复用已有能力/产物。

固定：

```text
Curriculum defines continuity.
Course Builder preserves continuity inside one lesson.
Workflow controls production sequence.
```
## 12. Current Course Builder / Workflow boundary

Current Course Builder 由 `skills/course-builder/index.ts` registry 解析；当前版本与生产状态以 `docs/CURRENT_SYSTEM_FACTS.md` 为准。本文件不保存 Skill 版本迁移历史。

连续性能力已经通过现行 Formal Brief + Course Production Workflow Context 解决。每次运行必须提供：

- current Track / Board owner；
- previous → current → next continuity；
- current Formal Brief / Formal Brief Batch；
- Deferred / Supporting Boundary；
- Grounding / Research Packet。

因此切换到 Track 02～05 **只替换 Context，不复制 Workflow，不新建 Track-specific Course Builder Skill**。只有出现新的、跨课程稳定语义职责且现有 Course Builder 无法通过 Context / Contract / Validator 表达时，才评估独立 Skill。

## 13. Future advanced course / media boundary

未来进阶课程可以是图文、流程图、截图、代码、实验或项目形式。

Course Builder 的职责仍是根据 Knowledge + Curriculum Position + Learner State 判断“这段知识怎样教最合适”。它可以提出 visualNeed / diagramBrief / screenshotNeed / codeExampleNeed / practiceNeed 等教学设计需求。

真正生成图片、视频、PPT 或其他 Media Asset 不属于 Course Builder，应由未来独立 Media Skill / Workflow 执行。

固定职责：

Course Builder = Instructional Design Intelligence
Media Skill = Media Production Intelligence
Workflow = Orchestration
