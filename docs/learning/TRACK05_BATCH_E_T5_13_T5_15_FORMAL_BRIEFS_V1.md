Boundary: **NO NEW UI / NO CSS / NO ENTERPRISE CHANGE-MANAGEMENT FRAMEWORK**

## T5-13 — 试点结束后，怎么判断继续、调整还是停止
Primary Knowledge Home: **Evaluation Decision / Baseline-to-Outcome / Investment Gate**
Core judgment: Pilot 结束后的决定必须回到原 Baseline、Success Condition、Value Hypothesis 和真实证据，而不是被几个成功案例或团队热情带走。
Must-retain judgments:
- 同口径比较 Baseline 与 Pilot Outcome；
- 区分结果改善、证据不足和副作用；
- Continue / Adjust / Stop 都是合法结论；
- 这是 post-Pilot gate，不重教 T5-06 pre-investment value hypothesis。
Practice: 学员自己的 Evaluation Decision；字段包括原基线、成功条件、Pilot 结果、风险副作用、证据质量、继续/调整/停止依据、希望 AI 帮我挑战什么。

## T5-14 — 方案明明有效，为什么团队还是不用
Primary Knowledge Home: **Adoption / Trust / Workflow Friction / Enablement**
Core judgment: 技术有效不等于会被采用；采用问题要观察信任、操作摩擦、工作位置、能力、激励和反馈，而不是简单归因于“用户抗拒变化”。
Must-retain judgments:
- 不使用可能是流程摩擦，不等于反对方案；
- 采用证据来自真实行为而非口头表态；
- 解决 adoption 可以调整流程/说明/支持，不必先改技术；
- 不进入 T5-15 长期 Owner/Operating Model。
Practice: 学员自己的 Adoption Friction Map；字段包括谁没用/少用、具体场景、可观察摩擦、用户反馈、当前支持方式、希望 AI 帮我区分什么。

## T5-15 — 从“有人试用”变成真正的工作方式，需要谁长期负责
Primary Knowledge Home: **Rollout / Ownership / Operating Model / Feedback Loop**
Core judgment: 正式采用后必须明确谁负责结果、谁维护内容/数据/权限、谁处理异常、谁收集反馈与决定版本变化；没有长期责任就只是一次项目。
Must-retain judgments:
- Pilot Owner 不自动等于长期 Owner；
- 运行责任、业务结果责任、技术支持可以分开；
- Rollout 要定义支持、反馈、变更与退出机制；
- 不把组织设计扩展成完整 RACI/企业治理课。
Practice: 学员自己的 Rollout & Ownership Plan；字段包括长期使用范围、业务 Owner、运行维护、异常处理、反馈机制、变更决策、希望 AI 帮我找责任缺口什么。

## Cross-lesson acceptance
T5-13 决定投不投；T5-14 解决为什么不用；T5-15 解决谁长期负责。三课不能互相提前。
