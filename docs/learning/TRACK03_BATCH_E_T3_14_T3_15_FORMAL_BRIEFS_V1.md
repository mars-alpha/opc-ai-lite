## Batch goal
把本板块前面的业务环节收束成可持续复盘循环：
**把关键指标连起来 → 判断这一轮发生了什么 → 决定下一轮保留 / 修改 / 停止 / 继续验证**。

## T3-14 — 内容、线索、销售、客服到底看哪些数字
Primary Knowledge Home: 运营指标树 / 业务链路复盘。
- 业务链路：曝光 → 行动 → 线索 → 跟进 → 成交/服务。
- 每个指标必须有定义、来源、时间范围和业务含义。
- Practice：最小指标树 + 相邻计算关系 + 能说明 / 不能说明 + 缺失数据。
- AI 可计算与解释；不能替业务定义成功标准、预算或因果。
- UI FIT：不新增数据看板编辑器。
- Capability：知道哪一段变化值得继续调查。

## T3-15 — 这轮做完以后，下一轮到底改什么
Primary Knowledge Home: 反馈循环 / 增长复盘。
- 事实 / 解释假设 / 行动决定分离。
- Practice：发生什么 → 为什么（证据 / 假设）→ 保留 / 修改 / 停止 / 继续验证 → 负责人和验证方式。
- 每个关键动作都要有事实依据、负责人、执行时间和验证方式。
- 不扩展到其他板块；本课只完成增长复盘与下一轮行动。
- Capability：把“看数据”推进到“改变下一轮业务动作”。

## Acceptance
T3-14 不把相关性写成因果，不让 AI 自定成功标准。T3-15 必须让下一轮动作引用真实事实，并写清负责人和验证方式；不得加入与本课无关的后续板块目标。
