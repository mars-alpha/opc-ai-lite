## 批次目标与输入

把前三课已经澄清并核验的信息，变成适合对象和目的的表达，再组织成有资料依据的成品，最后诊断和修改成品。三课可以自然复用同一份资料与草稿，但各自的练习必须独立可做。

## T2-04 — 同样的信息，怎么针对不同人表达

- Type / Gate：APPLICATION；CHECK + PRACTICE。
- Primary Knowledge Home：Audience / Purpose Fit。
- Learner Question：同样的信息，为何写给负责人、同事和客户时不该只改语气？到底先改什么？
- 当前任务：给定一组已确认事实，明确一个真实接收对象、沟通目的、对方已有背景和希望对方采取的下一步，再写一版可发送的表达。
- 继承：T2-03 的证据边界可作为资料；单课同时提供完整示例事实。调用 Prompt / Context，不重复教学提示词结构。
- 新能力：区分“事实不能变”与“解释深浅、排序、重点、行动要求可以变”；不能凭空推断读者需求或承诺。
- 产物：一份对象和目的都明确的短沟通稿。为下一课提供表达决策，但不强制作为 T2-05 输入。
- EXPLAIN：从“给谁都写同一版”切入，点明事实相同不意味着信息组织相同；底部说明区分接收对象与沟通目的。
- EXAMPLE：给出同一组已核事实，分别写给需要决定预算的负责人和需要配合试行的同事；两张对比卡说明各自最需要知道的依据与行动，展示保留事实而调整顺序和解释的结果。不得复用 Step 1 的场景句作为完整案例。
- CHECK：最佳判断（负责人需要先看到什么）；误区（只换敬语就算对象适配）；边界（保留哪些已核事实、哪些对方背景须先确认）。
- PRACTICE：用随课示例素材写给指定对象；字段覆盖原始事实、对象已知背景、沟通目的、输出与可确认的行动要求。按字段顺序复制后是一份可让 AI 直接写出沟通稿的任务；参考填充必须有具体真实样例值。
- REVIEW：AI适合依据已确认对象和目的重组表达、标记读者可能不懂的地方；不应该替人虚构对方的需求、权限、态度或团队承诺。下方解释“信息排序”与“事实改写”的界线。
- CAPABILITY：能用同一份事实写出面向不同接收者的两种有效表达，并解释为何不同。触发：要发工作说明却只会说“帮我写得专业一点”。下一课将把表达决定用于完整交付物。
- Deferred：不讲 ICP、客户分层、营销说服、转化话术；这些由 Track 03 决定。

## T2-05 — 一堆资料，怎么变成能交付的成品

- Type / Gate：APPLICATION；CHECK + PRACTICE。
- Primary Knowledge Home：Source-to-Deliverable Transformation。
- Learner Question：手上有几段资料，为什么 AI 的“总结”还不是能交给别人的工作成品？
- 当前任务：把明确给定的资料转成有对象、有目的、有结构、有依据边界且能供人继续编辑的短简报。不能要求用户连接外部文件或搜索。
- 继承：T2-04 的对象/目的判断和 T2-03 的证据边界；单课自带示例资料与任务。调用结构化输出直觉，不重教 Schema。
- 新能力：先界定交付物的用途与读者，再选择和组织有依据的材料；把资料中没有的内容留成待确认，不因结构完整就填入假事实。
- 产物：有“背景、已确认事实、目前限制、下一步建议/待确认”结构的简报草稿；可供 T2-06 诊断，但后课不强制依赖。
- EXPLAIN：区分“把资料概括一下”和“让接收者据此做事”；底部说明明确交付物需要回答的工作问题。
- EXAMPLE：示例包含几条有出处的事实和一条待验证的推测；对比散乱摘要与依据清楚、边界明确的短简报，两张卡分别呈现信息选择和产物结构的变化；结果说明接收者能做什么。
- CHECK：最佳判断（要先确定哪一种成品）；误区（AI 可以补全资料缺失的数字）；边界（哪些内容可以组织进成品，哪些必须标待确认）。
- PRACTICE：给随课资料包与明确读者，组合目的、原始资料、结构和事实使用规则，直接复制给 AI 可得到一份有依据的简报正文；必须完整提供示例资料，不把“见上一课”当唯一输入。
- REVIEW：AI适合整理、起草、压缩和重新组织已有资料；不应制造原资料没有的结论、数字或批准事项。下方说明成品完整性与事实可靠性两层检查。
- CAPABILITY：能从资料直接组织一份可检查的工作简报，并逐项指出依据和空缺。触发：资料很多、需要交一份成果却只能得到泛总结。下一课会检查初稿哪里未达交付标准。
- Deferred：不进入文件上传器、正式 PPT 排版、报告自动发布或 Track 03 内容营销系统。

## T2-06 — AI 已经写出来了，但“不好”，到底怎么改

- Type / Gate：APPLICATION；CHECK + PRACTICE。
- Primary Knowledge Home：Editorial Diagnosis / Revision。
- Learner Question：AI 初稿看着不对，怎样先识别具体缺陷，再提出能验证的修改要求？
- 当前任务：面对一份有明确问题的短成品，指出“原始资料事实不符 / 漏了信息 / 结构不合目的 / 重点或行动模糊”等真正缺陷，再给 AI 精确修订任务。
- 继承：T2-05 的成品草稿可选复用，单课必须自带资料与问题初稿。调用 Track 01 定向迭代，不从定义重教“怎样重复问 AI”。
- 新能力：先按“事实与依据、信息完整、结构与目的、表达与行动”诊断；每个修改要求可在修订结果中检查，已正确的部分标明保留。
- 产物：一份诊断说明 + 可直接交给 AI 的定向修订任务（以及可检查的修订稿）。
- EXPLAIN：从“再专业一点”为什么没法验收切入；底部说明区分个人感觉与可检查的缺陷。
- EXAMPLE：展示一份面向负责人的试行建议草稿，它把未核数字写成事实且没有明确决策请求；两张卡分别说明如何诊断事实问题与行动缺口，再给出局部修订要求与结果。不得把 Step 1 的泛场景变成 Step 2 全文。
- CHECK：最佳判断（优先修复哪类缺陷）；误区（重写整篇总比定向修改有效）；边界（资料不支持时应标待确认，不应补假数）。
- PRACTICE：给随课资料和初稿，要求 AI 按学员明确诊断只修指定位置、保留正确事实、标出资料不足、提供修改对照；参考填充组合后必须是一份完整可执行修订请求。
- REVIEW：AI适合找出与目标不符之处并按明确要求重写；不应替人决定事实是否成立、业务立场或最终批准。下方说明“哪里不好”如何转换成“怎么验证已改好”。
- CAPABILITY：能指出具体缺陷、写出有检查标准的修订要求，判断修订是否真正改善。触发：成品“不好”却只会让 AI 重新生成。下一阶段将在更长的资料与多文件中应用目标阅读。
- Deferred：不教营销内容体系、品牌调性策略或审批工作流。
